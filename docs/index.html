Inside an application

The model proposes.
Your app decides.

  1. 1

    Your app offers its tools.

    Send the request with the tools the person may use right now, plus the current date-time and device in the system message so “tomorrow” resolves correctly.

  2. 2

    The model returns a call or a reply.

    A function call with arguments, JSON for a schema, one shell command, or a question or refusal in words when no tool fits or a detail is missing.

  3. 3

    Your app checks, confirms and runs.

    Allow only known tools, validate the arguments, and ask the person before anything that sends, pays, deletes, shares or runs. Then send the result back for the final reply.

Where it leads

Of the tiny open models we tested, it most often declines when no tool fits, chooses the right shell behaviour (86%) and returns schema-valid JSON for unseen schemas (56%). It is also the fastest generator: 444 tokens/s at 4-bit on an Apple M6 GPU.

Where it is behind

Exact tool calls and instruction following. On BFCL v3 simple it scores 60% against 88–91% for both Granite 4.0 350M models, and on IFEval 26% against 47–53%. Qwen3-0.6B, with about 1.6 times the parameters, is also ahead on both.

Is the comparison fair?

The held-out sets are ours and follow this model’s prompt conventions, so they favour it. BFCL v3, IFEval and XSTest are neutral. On BFCL irrelevance, Qwen3-0.6B (88%) and SmolLM2 (75%) beat Udgam (68%).

03 / Build with it

Your tools.
Your application.

Download a GGUF from Hugging Face and run it with the provided Modelfile, or load the MLX or transformers weights. The repository has runnable examples for each runtime.

Use Q8_0 by default and Q4_K_M on phones. For tool use: temperature 0.1, top-p 0.9, top-k 40, repeat penalty 1.1. Context: 4,096 tokens.

Before you use it

A few honest answers.

Is this a chatbot?

It can chat, but it is built to be the language layer of an app: calling the app’s functions, filling schemas and proposing shell commands. At 384M parameters it is fluent but often factually wrong, so it is not a knowledgeable general assistant.

Can I let it act on its own?

No. On tools it has never seen, about one call in three is exactly right, and it sometimes guesses a value instead of asking. Keep an allowlist of tools, validate arguments and confirm anything consequential. Never auto-execute its shell commands.

Is it safe for open chat?

It is not safety-hardened. On XSTest it declines 54% of clearly harmful prompts and over-refuses 15% of safe ones. Put a moderation model or policy layer in front of open chat that people use.

Will it run on my phone or laptop?

The 4-bit GGUF is 238 MB and used about 323 MB of RAM in a CPU run on a Mac. On an Apple M6 GPU it generates about 444 tokens per second. Phones are slower, so measure your own device.

How was it trained?

From scratch, with no weights from any other model: pretrained on roughly 8B tokens of licensed public and synthetic text, then post-trained with supervised fine-tuning for chat and tool use. The technical report gives an overview of the architecture and evaluation.

What are the limits?

English only, a 4,096-token context (2,048 for the base model), and best results with the prompt conventions in the integration guide. Some agent apps send hidden prompts longer than 4,096 tokens, which do not fit.

What are the release terms?

Apache-2.0 for the weights, tokenizer, documentation and example code. The chat template is the official Gemma 4 template (Apache-2.0).
